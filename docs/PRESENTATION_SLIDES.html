Problem Statement & Objectives
Stage 1 & Stage 2 Overview
⚠️ The Challenge

High-frequency active data consumes RAM, but disk storage is too slow for real-time applications. Systems require low-latency memory management to move cold data to disk.

🎯 Project Objectives
  • Build Linux Character Driver (/dev/hotcold_dev).
  • Develop C++ Hot RAM & Cold Disk orchestrator.
  • Monitor system CPU/RAM via Linux /proc.
  • Provide interactive POSIX Socket CLI.

Linux Device Driver Layer (/dev/hotcold_dev)
Kernel Driver & User-space Fallback Interface
Kernel Character Driver

Registered via alloc_chrdev_region() and cdev_add(). Features 64-entry kernel ring buffer with spinlocks, ioctl commands, and sysfs stats.

User-Space Fallback

Implements a C++ software ring buffer emulator. Ensures 100% execution compatibility on systems without kernel header privileges.

C++ Engine & Storage Tiering
Memory Management & Concurrency
  • Hot RAM Tier: High-speed std::deque buffer for fast read/write access.
  • Cold Disk Tier: Automatic flushing to persistent log file when RAM capacity limit is reached.
  • Concurrency: Thread-safe access via std::shared_mutex (multiple readers, single writer).
  • Memory Safety: Smart pointers and RAII eliminate memory leaks.
Linux /proc Process Inspector
Software Process & System Resource Monitoring

Reads Linux Virtual Filesystem files without physical hardware:

/proc/stat

Parses CPU user, system, and idle ticks to compute CPU utilization percentage.

/proc/meminfo

Parses MemTotal and MemAvailable to track system RAM consumption.
